# Agent notes

- Tests under `tests/layout-gen` and `tests/ipmt` are
  autogenerated. Do not edit them by hand.
- Regenerate via the project's test/generation workflow when specs or the parser
  change: `make sync-test-cases` then `make gen-test-md`.
- Run `make layout-test` after any layout change; the corpus is gated on the
  semantic validator.
- Use `go run ./cmd/<tool>` / `go run ./cmd-dev/<tool>`; don't depend on prebuilt
  binaries.
- Scratch SVGs / debug renders go in `temp/`, never `/tmp/`.
- Layout analysis (bugs, questions, fixture pins) uses ONLY the layout debug
  tooling — `layout-debug --why/--facts/--candidates/--sel/--check`,
  `cmd-dev/layout-explain` (narrated report)
  (`docs/dev/layout-gen/layout-debug.md`). No ad-hoc bash/python/jq over
  layout output; if the tooling can't answer, extend it first, then answer
  through the extension.
- `.ipmt` files are considered documentation.
- Layout catalogue examples (`docs/dev/layout-gen/layout-alg.md`,
  `layout-alg-ext.md` and their corpora) use ABSTRACT node names — `e1/e1a`
  events, `tA/tA1` things, `cX` concepts; a structural role rides as a suffix
  on a kind+number id (`e1-hub`, `e2-sink`, `t1-shared`, `c1-note`) — never
  domain vocabulary, never a bare role word. The catalogue is about geometry;
  real worked examples with real labels belong in `docs/ipmt-ex/` and the
  tool docs.
- Follow KISS and YAGNI. Backward compatibility is not required in this phase.
