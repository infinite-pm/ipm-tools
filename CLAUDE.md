# ipm-tools — Claude notes

Parser + validator + layout engine + renderers for the `ipmt` text format.
See `agents.md` for the autogenerated-fixture rules, `README.md` for the pipeline,
and `docs/dev/` for internals.

## Validation gates — run before/after changes

```bash
go build ./...
go test ./...
make layout-test      # both layout corpora (base + ext), gated on the semantic validator
```

## Layout engine — checklist after ANY pkg/layout change

The fitness corpora assert precise per-shape geometry, but real diagrams hit
combinations no fixture anticipates — an engine change that keeps fitness green
can still put a node on top of another in an example file. Run ALL of these:

Note the corpora do NOT reach `OrderSharedPorts` or `DetourBlockedEdges`
(`gl:docs/dev/layout-gen/layout7-engine.md` "Post-placement passes"): nothing in
this repo calls them, so a change there is green here and still wrong for the
consumer that does. They have their own unit tests
(`gl:pkg/layout/detour_test.go`, `gl:pkg/layout/ports_order_test.go`); measure a
real change against a consumer's own corpus.

```bash
go build ./... && go test ./...
make layout-fitness     # base (tests/layout-gen) + ext (tests/layout-gen-ext)
make layout-check       # universal invariants (no node overlap, no edge through
                        # a node) over both corpora (Makefile CHECK_PATHS),
                        # ratcheted vs tests/layout-check-baseline.txt
                        # — FAILS if any file's finding count grows; when your
                        # change shrinks counts, run `make layout-check-baseline`
                        # and commit the tightened baseline.
                        # VISIBILITY-AWARE: edges the canvas hides behind "?"
                        # badges (cross-shell / >400px expresses & near-to —
                        # Edge.Visibility, stamped once on routed geometry and
                        # consumed in pkg/layout/edge_stubs.go)
                        # are excluded from edge metrics; their badges get the
                        # least-severe 4th column. --legacy-all-edges restores
                        # the old measurement for comparisons.
                        # After sync/moving cases: `make refs-rehash` (the
                        # runner silently DROPS cases missing outputs.ipmt)
make build-all          # refresh bin/ — SHIPPING plus the dev binaries
                        # (layout-debug, layout-explain). Do not skip: bin/ is
                        # gitignored and stale binaries run the OLD engine, so
                        # `bin/layout-debug --table` silently disagrees with
                        # `go run ./cmd-dev/layout-debug` and sends a diagnosis
                        # the wrong way. `make build-rpc` alone covers only
                        # ipm-rpc; `make build-dev` alone covers only the two.
```

Then see what the change actually MOVED — the corpora say whether anything
pinned broke, not what changed:

```bash
make layout-audit          # HEAD vs the working tree; OLD=<ref> to pick another
make layout-audit-ext      # the same over the EXTENDED corpus (sibling checkouts,
                           # the lab's SST corpus; its outliers skipped) — run both
```

It sweeps both corpora, `examples/` and every doc diagram through the engine at
`OLD` and the one in the working tree, ranks every diagram that changed
(invariant regressions first, then structural, then geometry) and writes
`temp/layout-audit/index.html`. Open it: a change that is green on fitness AND
on the ratchet can still have moved a diagram nobody pinned — that is what this
catches, and it is where the "snapshot the examples before/after" step below
now happens automatically. `gl:docs/dev-tools/layout-audit.md`. The default
set is small diagrams; NDA-scale faults show only in the extended corpus.

The zoom canvas (ipm-drawio) is the engine too — every click-path state is a
layout7 run with `Options.Shells`/`Options.Anchor`. An engine change that
touches placement or routing: `make zoom-check` in `../ipm-drawio` (the zoom
ratchet, `framecheck --corpus --baseline`), and re-render the lab.

Then re-render the doc diagrams so a human can review them:

```bash
go run ./cmd/md-embed --in docs/dev/layout-gen/layout-alg.md --no-prune --force
go run ./cmd/md-embed --in docs/dev/layout-gen/layout-alg-ext.md --no-prune --force
```

(Never run `md-embed --in <file>` without `--no-prune` — prune deletes every
SVG not referenced by that single file.)

**Session examples are part of the validation.** The corpora ratchet only
covers committed fixtures — a scratch example being iterated on can regress
silently between changes. For EVERY engine change:

1. Before the change, snapshot each active example:
   `layout-debug --check --in <example>.ipmt` (findings) — keep the output.
2. After the change, re-run and DIFF: a new crossing, graze, overlap or
   through-node on ANY session example is a regression to fix or to justify
   explicitly (e.g. a crossing→graze downgrade is a win by the v7P9
   currency; a new crossing is not).
3. An example that exposed a rule gets PINNED as a fixture before the
   session ends — unpinned examples rot within a few engine changes.

When a visual bug IS found (sweep finding, example file, screenshot): rule
first — add a failing `ipmdev-layout-rule` case to `layout-alg.md` (base
behaviour) or `layout-alg-ext.md` (combinations), confirm it is red, then fix
the engine, then re-run this checklist.

## Layout engine

The engine map is `docs/dev/layout-gen/layout7-engine.md`; the principles it
implements are `docs/dev/layout-gen/layout-principles.md`; the behaviour
catalogue is `docs/dev/layout-gen/layout-alg.md`. The corpus under
`tests/layout-gen/` is the canonical regression set (plus the combination
corpus `tests/layout-gen-ext/` from `layout-alg-ext.md`); refresh with
`make sync-test-cases` + `make gen-test-md` after intended changes.

## Layout analysis — the debug tooling is the ONLY allowed way

Any layout question, bug hunt or fixture derivation goes through the layout
debug tooling (`docs/dev/layout-gen/layout-debug.md`) and NOTHING else:

```bash
go run ./cmd-dev/layout-debug --in case.ipmt --why [--candidates] [--sel a,b]
go run ./cmd-dev/layout-debug --in case.ipmt --facts
go run ./cmd-dev/layout-debug --in case.ipmt --check          # invariants, one diagram
go run ./cmd-dev/layout-explain --in doc.md --block "heading" # narrated .md report + SVG
```

Explicitly FORBIDDEN for layout analysis: ad-hoc bash/jq/grep pipelines over
`.layout.json` or SVGs, one-off python scripts, `println` debugging inside the
engine. If the tooling cannot answer a question, EXTEND it first (emit site in
`pkg/layout7/trace.go`, view in `pkg/l7report`, tool flag) and answer through
the extension — that extension is part of the deliverable. Rendered SVGs stay
the visual ground truth; `--facts` covers relation checks without a render.

## Conventions

- Scratch / debug renders go in `temp/`, never `/tmp/`.
- T/C parent-child relationships ride on `expresses` edges; event containment
  rides on `partof` (event→event only).
